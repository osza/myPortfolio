Case study

Mews Events

Documentation architecture and content restructuring for a newly integrated module used to manage quotes for hotel-hosted events.

Back to portfolio Open documentation hub

Context

Overview

This case study shows how I approached documentation architecture for a newly integrated product area and reorganised fragmented internal material into a release-ready public documentation hub.

Starting point

New module · Fragmented source material

Mews Events, originally quotello, was brought into the Mews product ecosystem as a module for event quotes and related workflows. Before release, the available knowledge existed mainly as fragmented internal notes, intended largely for support use and not yet structured for public help content.

Contribution

What I did

My role combined information architecture, content design, system organisation, and writing for a product area that needed to fit the broader Mews help model from day one.

Structure

Documentation architecture

I designed the overall documentation structure for the new product area, including navigation nodes, article grouping, and a model that aligned the module with the existing Mews help center.

System design

CMS organisation

I defined internal CMS structure in Salesforce, including templates, cross-linking patterns, and tagging, so the content would be easier to manage and expand over time.

Content

Public-facing help content

I reshaped support-oriented source material into public-facing documentation that was clearer, easier to find, and more useful for end users following real workflows.

Problem

The documentation challenge

The module needed to be documented quickly, but the source material was not structured for end users and did not yet fit Mews documentation standards.

Main constraints

Migration · consistency · usability

  • The existing material was fragmented and largely support-oriented.
  • The new area needed to fit an established help center model and taxonomy.
  • Users needed task-focused content, not internal implementation notes.
  • The structure had to support future expansion and localization.

Approach

How I structured the work

I approached the project as both a content and systems problem, so the published articles would be useful immediately and maintainable later.

Information architecture

I mapped the module into a clear help center structure with logical entry points, article groupings, and user-oriented navigation.

Content design

I translated internal operational knowledge into public-facing documentation focused on tasks, concepts, and discoverability.

Operational setup

I organised the CMS layer in Salesforce so the content model would be easier to maintain, connect, and scale.

Outcome

Result

The project delivered a documentation area that matched the rest of the Mews help center and gave the module a clearer public-facing entry point.

Clarity

Usable public structure

The documentation was reorganised into a model that was easier for customers to browse and understand.

Consistency

Aligned with Mews standards

The new content fit the established help center architecture instead of feeling like a separate imported product.

Scalability

Ready for future growth

The CMS and content structure supported later additions, editing, and long-term documentation maintenance.
