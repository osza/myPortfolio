Approach

What I focus on when writing tutorials.

Across API and SUI topics, I use the same writing principles: reduce ambiguity, guide the reader through decisions, and organise information so it supports action rather than only passive reading.

Task orientation

Readers usually come with a goal, not with time to absorb everything. I write tutorials so that the next useful step is easy to find.

Terminology control

Technical wording should be precise, but it also needs to remain readable. I aim for language that supports both accuracy and comprehension.

Progressive explanation

Good tutorial structure introduces concepts in the order a reader needs them, rather than presenting everything at once.

Fit

Where this kind of writing is useful.

This kind of material is useful when a team needs more than reference text: onboarding sequences, guided technical education, feature explanation, and documentation that helps users or developers complete real tasks with less friction.

Onboarding

Tutorials that help readers start using a product, API, or concept with less guesswork.

Content that supports understanding, adoption, and confident use across technical audiences.
