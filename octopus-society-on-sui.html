Workflow

Join and verify

The core of the tutorial is a practical sequence that shows the membership flow from joining to on-chain verification.

Step 1 · Connect a wallet

Start by connecting a wallet in Sui Wallet or your preferred browser extension. The tutorial keeps the action lightweight so the reader can focus on the membership logic.

  • Confirm the wallet is set to the intended network.
  • Check that the account has enough test SUI for gas.

Step 2 · Join Octopus Society

Submit the join transaction against the Move module to mint a membership object. The tutorial shows both the command-line flow and the equivalent TypeScript call.

  • Capture the transaction digest.
  • Store the newly created membership object ID.

Step 3 · Verify membership

Use the object ID to confirm ownership and inspect the membership fields. This reinforces the object-centric mental model used throughout the tutorial.

  • Query the object through the CLI.
  • Repeat the check with the SDK response.

Step 4 · Claim the reward

Finish by claiming a reward tied to the membership. The final step closes the onboarding loop and gives the tutorial a concrete outcome.

  • Confirm the reward transaction succeeded.
  • Review the updated object state after the claim.

Code

CLI and TypeScript examples

The examples below are intentionally practical: they show the actual flow a developer would follow to mint, inspect, and verify a membership object in Sui.

1. Join with Sui CLI

Run the transaction from the terminal

Use the CLI when you want to validate the contract entry point quickly and see the transaction output before wiring it into an app. 

sui client call \
  --package <PACKAGE_ID> \
  --module octopus_society \
  --function join \
  --args <WALLET_ADDRESS> \
  --gas-budget 10000000

The call mints a membership object and returns a transaction digest that you can use to inspect the result.

2. Verify the membership object

Check ownership and state

After the join transaction succeeds, inspect the object directly so the reader sees the same data the game or app will later consume. 

sui client object <MEMBERSHIP_OBJECT_ID>

In a real tutorial, this is where you explain which fields matter: owner, membership tier, join timestamp, and reward eligibility.

3. Join from TypeScript

Embed the flow in a game or web app

This version is better for a game client or documentation example because it shows the same action from application code. 

import { SuiClient, TransactionBlock } from '@mysten/sui.js';

const client = new SuiClient({ url: 'https://fullnode.testnet.sui.io' });

const tx = new TransactionBlock();
tx.moveCall({
  target: `${packageId}::octopus_society::join`,
  arguments: [tx.pure(walletAddress)],
});

const result = await client.signAndExecuteTransactionBlock({
  signer: keypair,
  transactionBlock: tx,
});

console.log(result.digest);

This example makes the tutorial hands-on because it shows the exact call path a developer would wire into a game client, script, or demo app.

4. Read the object in TypeScript

Fetch the result and render it in UI

Use the object ID from the transaction result to render the current membership state in the app or game UI. 

const object = await client.getObject({
  id: membershipObjectId,
  options: { showContent: true, showOwner: true },
});

console.log(object.data?.content);

This closes the loop from transaction to UI and makes the tutorial genuinely useful for developers who need a working reference.
