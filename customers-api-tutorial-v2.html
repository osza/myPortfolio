This tutorial demonstrates an end-to-end workflow for managing customer data with a fictional Customers API. The API, URLs, and example data are provided to illustrate structure, flow, and documentation style.

By the end of the tutorial, you will have created a customer record, retrieved it by ID, updated selected fields, and deleted the resource.

Tutorial

Before you start

The setup section establishes the environment, credentials, and request tooling needed before the CRUD flow begins.

Requirements and setup

Authentication · Environment · Request tooling

Before you begin, make sure you have:

  • An API access token with permission to call the Customers API.
  • The base URL for your environment, such as sandbox or production.
  • A tool for sending HTTP requests, such as curl or Postman.
  • Network access to the /api/1.0/customers endpoint.

In the examples below, replace {base_url} and {access_token} with your own values. In a real application, you would typically store them in environment variables such as BASE_URL and ACCESS_TOKEN.

For safety, use a sandbox environment and a non-production token while testing this workflow.

Base URL and headers

Authentication and request format

All examples in this tutorial use bearer token authentication and JSON request bodies where applicable.

Authorization: Bearer {access_token}
Content-Type: application/json

Include the Authorization header in every request. Include Content-Type: application/json when the request contains a JSON body, such as POST or PATCH.

In a real implementation, handle HTTP status codes such as 201 Created or 4xx errors explicitly and log or surface error messages to make debugging easier.

Customers API snapshot

Endpoint overview

  • POST /api/1.0/customers — Create a new customer.
  • GET /api/1.0/customers/{id} — Retrieve a customer by ID.
  • PATCH /api/1.0/customers/{id} — Update selected fields on a customer.
  • DELETE /api/1.0/customers/{id} — Delete a customer.

The tutorial uses a partial update model for PATCH: only the fields included in the request body are changed.

CRUD tutorial

1. Create a customer

POST /api/1.0/customers

Create the customer record that you will use throughout the rest of this tutorial. The response returns its generated id, which you need for the retrieve, update, and delete requests.

curl --request POST \
  --url {base_url}/api/1.0/customers \
  --header "Authorization: Bearer {access_token}" \
  --header "Content-Type: application/json" \
  --data '{
    "full_name": "John Doe",
    "email": "john@doe.com",
    "business_name": "Northwind Studio"
  }'
const response = await fetch(`${baseUrl}/api/1.0/customers`, {
  method: "POST",
  headers: {
    Authorization: `Bearer ${accessToken}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    full_name: "John Doe",
    email: "john@doe.com",
    business_name: "Northwind Studio"
  })
});

if (!response.ok) {
  // Handle non-2xx responses in a real implementation
}

const customer = await response.json();

The client creates the initial customer record and obtains an id that you reuse in later requests.

const response = await fetch(`${baseUrl}/api/1.0/customers/${customer.id}`, {
  method: "GET",
  headers: {
    Authorization: `Bearer ${accessToken}`

});

3. Update the customer

PATCH /api/1.0/customers/{id}

Update selected fields on the existing customer without replacing the entire resource. This request changes the customer's name and business name while preserving fields that are not included in the request body.

curl --request PATCH \
  --url {base_url}/api/1.0/customers/{id} \
  --header "Authorization: Bearer {access_token}" \
  --header "Content-Type: application/json" \
  --data '{
    "business_name": "Northwind Labs",
    "full_name": "John A. Doe"
  }'
