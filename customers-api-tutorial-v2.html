API onboarding tutorial

Manage customer data with the Customers API

A hands‑on tutorial that walks through a complete customer lifecycle using create, retrieve, update, and delete operations on a single resource.

Overview

Tutorial sample · Fictional REST API

This tutorial demonstrates an end‑to‑end workflow for managing customer data with a fictional Customers API. The API, URLs, and example data are provided to illustrate structure, flow, and documentation style.

By the end of the tutorial, you will have created a customer record, retrieved it by ID, updated selected fields, and deleted the resource.

Before you start

Requirements and setup

Before you begin, make sure you have:

  • An API access token with permission to call the Customers API.
  • The base URL for your environment, such as sandbox or production.
  • A tool for sending HTTP requests, such as curl or Postman.
  • Network access to the /api/1.0/customers endpoint.

In the examples below, replace {base_url} and {access_token} with your own values. In a real application, you would typically store them in environment variables such as BASE_URL and ACCESS_TOKEN.

For safety, use a sandbox environment and a non‑production token while testing this workflow.

Base URL and headers

Authentication and request format

All examples in this tutorial use bearer token authentication and JSON request bodies where applicable. 

Authorization: Bearer {access_token}
Content-Type: application/json

Include the Authorization header in every request. Include Content-Type: application/json when the request contains a JSON body, such as POST or PATCH.

Customer resource

Field reference

The tutorial uses a single Customer resource with the following fields:

Field Type Required Description
id string (UUID) No Stable unique identifier generated by the API.
full_name string Yes Customer’s full name.
email string Yes Customer email address. Typically unique per customer.
business_name string No Optional company or organization name.
created_at string (ISO 8601) No Timestamp when the record was created.
updated_at string (ISO 8601) No Timestamp when the record was last updated.

Customers API snapshot

Endpoint overview

  • POST /api/1.0/customers — Create a new customer.
  • GET /api/1.0/customers/{id} — Retrieve a customer by ID.
  • PATCH /api/1.0/customers/{id} — Update selected fields on a customer.
  • DELETE /api/1.0/customers/{id} — Delete a customer.

This tutorial uses a partial update model for PATCH: only the fields included in the request body are changed.

1. Create a customer

POST /api/1.0/customers · 201 Created

Send a POST request to create a customer resource. On success, the API returns a stable id that you will reuse in the next three steps. 

curl -X POST "{base_url}/api/1.0/customers" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "full_name": "Pedro Oszenda",
    "email": "pedro.oszenda@example.com"
  }'
async function createCustomer() {
  const response = await fetch(`${baseUrl}/api/1.0/customers`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${accessToken}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      full_name: "Pedro Oszenda",
      email: "pedro.oszenda@example.com"
    })
  });

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return response.json();
}

Example 201 response:

{
  "id": "9c7c97a8-ac45-b778-8b38-26a74fdf1f6a",
  "full_name": "Pedro Oszenda",
  "email": "pedro.oszenda@example.com",
  "created_at": "2026-06-13T12:03:39Z",
  "updated_at": "2026-06-13T12:03:39Z"
}

2. Retrieve a customer

GET /api/1.0/customers/{id} · 200 OK

Send a GET request using the id returned in the previous step. 

curl -X GET "{base_url}/api/1.0/customers/9c7c97a8-ac45-b778-8b38-26a74fdf1f6a" \
  -H "Authorization: Bearer {access_token}"
async function getCustomer(id) {
  const response = await fetch(`${baseUrl}/api/1.0/customers/${id}`, {
    method: "GET",
    headers: {
      Authorization: `Bearer ${accessToken}`
    }
  });

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return response.json();
}

Example 200 response:

{
  "id": "9c7c97a8-ac45-b778-8b38-26a74fdf1f6a",
  "full_name": "Pedro Oszenda",
  "email": "pedro.oszenda@example.com",
  "created_at": "2026-06-13T12:03:39Z",
  "updated_at": "2026-06-13T12:03:39Z"
}

3. Update a customer

PATCH /api/1.0/customers/{id} · 200 OK

Send a PATCH request to update selected fields on the customer. In this example, you add a business name without changing the existing email address or the original full name. 

curl -X PATCH "{base_url}/api/1.0/customers/9c7c97a8-ac45-b778-8b38-26a74fdf1f6a" \
  -H "Authorization: Bearer {access_token}" \
  -H "Content-Type: application/json" \
  -d '{
    "business_name": "Blahblah Ltd"
  }'
async function updateCustomer(id) {
  const response = await fetch(`${baseUrl}/api/1.0/customers/${id}`, {
    method: "PATCH",
    headers: {
      Authorization: `Bearer ${accessToken}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      business_name: "Blahblah Ltd"
    })
  });

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return response.json();
}

Example 200 response:

{
  "id": "9c7c97a8-ac45-b778-8b38-26a74fdf1f6a",
  "full_name": "Pedro Oszenda",
  "business_name": "Blahblah Ltd",
  "email": "pedro.oszenda@example.com",
  "created_at": "2026-06-13T12:03:39Z",
  "updated_at": "2026-06-13T12:10:13Z"
}

Only the fields included in the request body are updated. Other fields, such as full_name and email, remain unchanged.

4. Delete a customer

DELETE /api/1.0/customers/{id} · 204 No Content

Send a DELETE request to remove the customer resource. In this tutorial, DELETE represents a permanent delete. 

curl -X DELETE "{base_url}/api/1.0/customers/9c7c97a8-ac45-b778-8b38-26a74fdf1f6a" \
  -H "Authorization: Bearer {access_token}"
async function deleteCustomer(id) {
  const response = await fetch(`${baseUrl}/api/1.0/customers/${id}`, {
    method: "DELETE",
    headers: {
      Authorization: `Bearer ${accessToken}`
    }
  });

  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}`);
  }

  return;
}

Successful response:

204 No Content

A 204 No Content response indicates that the resource was deleted successfully.

Error handling

Typical error responses

When a request fails, the API returns an appropriate 4xx status code together with a JSON error payload.

Example 400 response when a required field is missing:

{
  "error": {
    "code": "invalid_request",
    "message": "The 'email' field is required.",
    "details": [
      {
        "field": "email",
        "issue": "missing"
      }
    ]
  }
}

Example 404 response when the customer does not exist:

{
  "error": {
    "code": "not_found",
    "message": "Customer '9c7c97a8-ac45-b778-8b38-26a74fdf1f6a' was not found."
  }
}
