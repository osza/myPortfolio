Overview

This sample is designed as a fuller API tutorial that adds setup context, resource explanation, and writing guidance on top of the basic CRUD flow.

What this tutorial covers

Tutorial sample · Fictional REST API

This tutorial demonstrates an end-to-end workflow for managing customer data with a fictional Customers API. The API, URLs, and example data are provided to illustrate structure, flow, and documentation style.

By the end of the tutorial, you will have created a customer record, retrieved it by ID, updated selected fields, and deleted the resource.

Preparation

Before you start

The tutorial assumes a common API testing setup with authentication, a base URL, and a request tool for exploratory development work.

Requirements and setup

Token · Environment · Request tooling

Before you begin, make sure you have:

  • An API access token with permission to call the Customers API.
  • The base URL for your environment, such as sandbox or production.
  • A tool for sending HTTP requests, such as curl or Postman.
  • Network access to the /api/1.0/customers endpoint.

In the examples below, replace {base_url} and {access_token} with your own values. In a real application, you would typically store them in environment variables such as BASE_URL and ACCESS_TOKEN.

For safety, use a sandbox environment and a non-production token while testing this workflow.

Reference

Base URL, headers, and resource model

Before the request sequence begins, the tutorial defines the request pattern and the resource fields used in the examples.

Base URL and headers

Authentication and request format

All examples in this tutorial use bearer token authentication and JSON request bodies where applicable. 

Authorization: Bearer {access_token}
Content-Type: application/json

Include the Authorization header in every request. Include Content-Type: application/json when the request contains a JSON body, such as POST or PATCH.

Customer resource

Field reference

The tutorial uses a single Customer resource with the following fields:

Field Type Required Description
id string (UUID) No Stable unique identifier generated by the API.
full_name string Yes Customer’s full name.
email string Yes Customer email address. Typically unique per customer.
created_at string (timestamp) No Timestamp generated when the record is created.
updated_at string (timestamp) No Timestamp generated when the record is last updated.

Customers API snapshot

Endpoint summary

Operation Method Path Purpose
Create customer POST /api/1.0/customers Create a new customer record.
Retrieve customer GET /api/1.0/customers/{id} Get one customer record by ID.
Update customer PATCH /api/1.0/customers/{id} Modify selected customer fields.
Delete customer DELETE /api/1.0/customers/{id} Remove the customer record.

Workflow

Customer lifecycle tutorial

The sequence below walks through one customer record from creation to deletion using a predictable request-and-response format.

1. Create a customer

POST /api/1.0/customers

Use a POST request to create a new customer record.

2. Retrieve a customer

GET /api/1.0/customers/{id}

Use a GET request to retrieve the customer by its stable id.

3. Update a customer

PATCH /api/1.0/customers/{id}

Use a PATCH request to update selected customer fields without replacing the whole record.

4. Delete a customer

DELETE /api/1.0/customers/{id}

Use a DELETE request to remove the customer record when it is no longer needed.
